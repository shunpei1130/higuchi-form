# higuchi-form

Expleeの公開画面と公開APIの業務仕様を参考にした、日本語のAI営業サービスです。AgentSDRを基盤として、事業の分析、キャンペーン、個別メール、返信対応、商談予約、従量課金をまとめて扱います。

Expleeの非公開実装やデータベースを取得したものではありません。ログイン前の6工程は確認した公開画面に沿って実装し、ログイン後の管理画面は公開仕様に基づく独立実装です。顧客データは後から用意するDB出力・CSV・Excelを運営者が取り込んで公開します。新しい外部顧客データサービスの契約は不要です。

## このコンピューターで試す

依存ライブラリをインストールした後、次を実行します。Node.js 24を使用してください。

```powershell
npm run dev:local
```

[http://127.0.0.1:3000/](http://127.0.0.1:3000/) を開きます。初回はローカル設定を自動作成し、架空のサンプルを用意します。実際のメール送信、AI呼出し、料金の請求は行いません。サーバーはこのコンピューターからのみ接続できます。

依存ライブラリを入れ直す場合は、`npx --yes bun@1.3.14 install --frozen-lockfile` を実行してください。以下の手順も、Bunをシステムへインストールせずに使える`npx`形式で記載しています。Bun 1.3.14がPATHにある環境では、`npx --yes bun@1.3.14`を`bun`に置き換えられます。

## 操作の流れ

1. トップから会社URLまたは事業内容を入力し、プロジェクトとキャンペーンを作成します。
2. サンプルの顧客候補を確認するか、CSVを取り込みます。検証用の架空データは画面に明記します。
3. 「利用状況・請求」で支払方法の確認を模擬実行し、無料クレジットを付与します。
4. キャンペーンの予算・文面・送信曜日を確認して開始します。レビュー待ちの場合は明示的に承認するか、検証用の時間を進めます。
5. 「検証を進める」や返信・予約の模擬操作で、受信箱、商談、利用履歴の変化を確認できます。
6. 停止すると送信と自動返信が止まります。アーカイブでは保留送信を取り消し、復元後も自動返信はオフです。

検証データはOSの一時フォルダー内の `higuchi-form/<プロジェクト識別子>/simulation/` に保存され、署名付きCookieでブラウザーごとに分離します。保存先はソースコードの監視対象から分けています。このフォルダーと `.env.local` は共有しないでください。設定画面から自身の検証データを初期化できます。

## 本番接続

PostgreSQL 16以上、Vercel Pro以上、公開HTTPS URLを使用します。`.env.example` を参考に設定し、`HIGUCHI_MODE=live` を明示してください。変数がない場合も本番接続として扱い、接続不足から検証環境へ自動で切り替えることはありません。

新しいデータベースの作成：

```powershell
npx --yes bun@1.3.14 run db:setup
npx --yes bun@1.3.14 scripts/db/higuchi-setup.ts
npx --yes bun@1.3.14 scripts/db/higuchi-preview.ts
npx --yes bun@1.3.14 scripts/db/higuchi-catalog-guarantee.ts
```

既存のAgentSDRデータベースでは `db:setup` を再実行せず、バックアップ後に上記3つの追加スキーマを順番に適用します。各スクリプトは`--check`で接続なしの確認ができます。適用には`DATABASE_URL_UNPOOLED`の直接接続を使用し、既存の組織データは削除しません。

公開前は`HIGUCHI_PUBLIC_PREVIEW=false`で匿名調査を停止します。この場合、トップの入力は従来のログイン後の事業設定へ進みます。スキーマ、OpenAI予算、円建てStripe設定を確認してから`true`にします。公開時はURL入力→会社調査→競合調査→3〜6キャンペーン→企業候補→意思決定者→個別メールの順に進み、ログイン前に文面まで確認できます。

匿名結果は24時間保存します。期限後は入力・調査内容・連絡先・文面を消去し、費用台帳と取り込み済みの管理画面データは保持します。顧客データが未公開なら候補とメールをサンプルと明記し、カード登録・決済・送信はできません。公開データに一致する候補が0件の場合は、サンプルへ置き換えず0件と表示します。

Dockerの場合は秘密情報を環境変数に設定して、ソースからビルドします。

```text
docker compose -f docker-compose.higuchi.yml up --build -d
```

空のデータベースでは初期化処理がスキーマを準備します。既存のDockerボリュームにも、上記の追加スキーマを適用してください。本番の定期処理はVercelの毎分Cronで起動し、ジョブはPostgreSQLに保存します。

本番では以下を接続します。未設定の機能は成功扱いにせず、理由を画面に表示します。

| 用途 | 接続先 |
|---|---|
| ログイン・認証メール | Better Auth、Resend |
| LinkedInログイン | 任意のLinkedIn OAuthアプリ |
| 事業分析・メール作成・返信 | OpenAI API（gpt-6-luna、アプリ全体で月20米ドル上限） |
| 営業メール・受信 | 運営側のGoogle Workspace、専用メールボックス |
| 予約・変更・取り消し | 内蔵予約（日本時間） |
| 支払方法・前払い | Stripe |
| 従量課金・クレジット・請求 | Stripe Meters・Credit Grants・Subscriptions |

運営者設定は `/operator` です。初期組織のオーナー・管理者のみ操作できます。Googleメールの本人認証、AI利用額、予約公開設定、Stripe顧客・契約の関連付けを扱います。顧客データの取り込み・公開は`/operator/catalog`、返金保証の審査は`/operator/refunds`です。詳細は [接続手順](docs/higuchi-integrations.md) を参照してください。

## 課金・自動営業の扱い

- 新しい円建て利用は営業メール1通6円、返信は無料です。金額は整数の円で保存します。既存USD顧客は整数セントと旧料金を保持し、自動換算しません。送信先プロバイダの受付確認後に利用を確定します。
- 日額・月額の上限はUTC境界で集計し、表示は日本時間にします。送信前の確保額も予算に含めます。
- カード確認の完了通知を検証してから4,500円分の無料枠を付与します。前払いは4,500円・7,500円・15,000円で、初回対象者は2倍のクレジットを受け取れます。無料枠と初回前払倍額特典は併用しません。
- 円建ては`HIGUCHI_BILLING_CURRENCY=JPY`と専用の`STRIPE_JPY_*`を設定します。埋め込み決済の`STRIPE_PUBLISHABLE_KEY`はVercelの暗号化環境変数へ保存します。円用・旧ドル用のカタログやテスト・本番のキーは混在させません。
- 実候補と保存済み文面を本人確認後に取り込み、支払方法、利用規約、初回・追客・設定に従う返信対応の開始を確認します。匿名画面の表示やログインだけでは送信しません。決済結果は署名付きWebhookで確定します。
- 自動予算配分は、確認済み送信数・返信・商談を使ってUTC日ごとに一度実行します。手動停止したキャンペーンを勝手に再開しません。これは今回採用した方針であり、Expleeの内部アルゴリズムを特定したものではありません。
- 送信結果不明は自動再送せず保留します。課金イベントは永続キューと一意なイベントIDで再試行します。
- 本番公開前に、送信ドメインの認証、送信元の準備、提供条件、運営者情報、問い合わせ先、販売条件を確定してください。

## 開発と確認

```text
npx --yes bun@1.3.14 run test:higuchi
npx --yes bun@1.3.14 run --conditions=react-server scripts/e2e/higuchi-smoke.ts
npm run typecheck
npx --yes bun@1.3.14 run build
```

HTTPの通し確認は、検証モードのサーバーを起動してから実行します。テスト用の独立セッションを使い、既存のブラウザーセッションを初期化しません。

`npm run build`は内部でBunを呼び出すため、BunがPATHにない環境では上記の`npx`形式を使ってください。

確認記録は`design-qa.md`、`docs/higuchi-verification.md`、最新の接続状態は`docs/higuchi-production-status.md`を参照してください。接続設定や模擬試験の成功だけでは、営業メールの実送受信・LIVE決済・通知配送の一連の動作を検証済みとは扱いません。
